# Персональный индекс: шпаргалка

## Основные понятия

- **Запись** — данные об одном человеке.
- **Атрибут** — поле записи, например год рождения.
- **Ключ индекса** — значение, по которому организован поиск.
- **Составной ключ** — несколько атрибутов, сравниваемых вместе.
- **Группа записей** — массив людей, имеющих один ключ индекса.

`id` здесь обычное поле, а не ключ дерева. Индекс не запрещает одинаковые `id`.

## Зачем нужны два индекса

```text
Запись: {1, Ada, Lovelace, 1815}

(имя, фамилия, год) → [записи]    точное совпадение
год                → [записи]    диапазон годов
```

Порядок `(имя, фамилия, год)` не группирует все записи одного года рядом: сначала учитывается имя. Поэтому для эффективного диапазона годов используется отдельное дерево.

Цена ускорения поиска — дополнительная память и необходимость изменять оба индекса при добавлении.

## Составной ключ

Кортежи сравниваются лексикографически: первое различающееся поле определяет порядок.

```text
(Ada, Lovelace, 1815) < (Ada, Lovelace, 1816)
(Ada, Lovelace, 1816) < (Alan, Turing, 1912)
```

Точный запрос требует всех трёх полей. Наличие составного индекса само по себе не означает поддержку поиска только по фамилии или году.

Два человека могут иметь одинаковые имя, фамилию и год рождения. Поэтому значение дерева — массив записей, а не одна запись. При совпадении ключа запись добавляется в существующую группу.

## Добавление

Для каждого из двух индексов:

1. Вычислить ключ.
2. Если ключ отсутствует, создать пустую группу.
3. Добавить копию записи в группу.

Поиски и вставки в красно-чёрное дерево логарифмические по числу разных ключей. Добавление в динамический массив обычно постоянно амортизированно, но при расширении копируются прежние элементы.

## Точный и диапазонный поиск

**Точный поиск:** спускаться по составному ключу в дереве. Если ключ найден, скопировать всю группу; иначе вернуть пустой массив.

**Диапазон `[a, b]`:** обходить дерево годов с отсечением ненужных ветвей. Если год меньше `a`, левое поддерево не подходит; если больше `b`, правое не подходит. Подходящие группы выгружаются по возрастанию года, затем объединяются.

Пример: для годов `1815, 1906, 1912` запрос `[1900, 1912]` возвращает группы `1906` и `1912`. Обе границы включены.

При `r` найденных записях невозможно выдать полный ответ быстрее `Ω(r)`. Поэтому логарифмическая сложность относится к нахождению ключа, а не к копированию всех результатов.

## Индекс и полное сканирование

| Способ | Поиск | Цена |
|---|---|---|
| Просмотреть все записи | `O(n)` | Не нужна дополнительная структура |
| Точный поиск по дереву | `O(log(c + 1) + r)` | Память и поддержка индекса |
| Диапазон по дереву годов | `O(log(y + 1) + k + r)` | Отдельный индекс по году |

Для запроса, возвращающего почти все записи, копирование ответа может определять большую часть времени.

## Что сказать на защите

- Почему `Map` не теряет людей с одинаковым ключом? Уникален ключ дерева, а его значение содержит несколько записей.
- Почему не хеш-таблица? Дерево поддерживает порядок и отсечение ветвей при диапазонном поиске; обычная хеш-таблица такого порядка не даёт.
- Где хранятся данные? В двух наборах копий, а не в общей таблице с указателями из индексов.
- Что происходит при изменении исходного `PersonRecord`? Индекс не меняется, поскольку хранит копию.
- Что мешает добавить обновление? Нужно согласованно удалить старые ключи и добавить новые в оба индекса.
- Что такое атомарность добавления? Либо оба индекса изменены, либо ни один. Текущая реализация этого при исключении не гарантирует.
