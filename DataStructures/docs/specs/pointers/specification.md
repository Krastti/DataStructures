# Спецификация умных указателей

## Назначение

Указатели управляют временем жизни динамически созданных объектов и освобождают ресурсы при завершении владения.

| Тип | Владение | Освобождение | Доступ |
|---|---|---|---|
| `UniquePtr<T>` | Единственный владелец | `delete` | `*`, `->` |
| `UniquePtr<T[]>` | Единственный владелец массива | `delete[]` | `[]` |
| `SharedPtr<T>` | Совместное владение | `delete` последним владельцем | `*`, `->` |
| `SharedPtr<T[]>` | Совместное владение массивом | `delete[]` последним владельцем | `[]` |

Это учебные реализации C++20. Совместимость со всем интерфейсом и поведением стандартных умных указателей не заявляется.

## Общие свойства

- Пустой конструктор, `nullptr` и типизированный нулевой указатель создают пустого владельца.
- `get()` пустого владельца возвращает `nullptr`, преобразование в `bool` — `false`.
- Конструктор из ненулевого сырого указателя принимает ответственность за его удаление.
- Переданный адрес должен допускать соответствующее удаление: одиночный объект через `delete`, массив через `delete[]`.
- Нельзя передавать адрес локального объекта, память из `malloc`, указатель внутрь массива или адрес, которым уже независимо владеет другой умный указатель.
- Тип должен быть полным в месте, где выполняется его удаление; деструктор должен быть доступным и не бросать исключения.
- Размер массива не хранится, границы не проверяются. Для массивов известной границы отдельная форма `Ptr<T[N]>` не поддерживается: используется `Ptr<T[]>`.

Сырой указатель не хранит сведения о том, выделен объект через `new T` или `new T[n]`. Вызывающий код обязан выбрать правильную специализацию. Вывод типа из `new T[n]` не распознаёт массив: нужно явно писать `UniquePtr<T[]>` или `SharedPtr<T[]>`.

## UniquePtr

### Создание и владение

Внутреннее состояние — один `T*`. Копирующие конструктор и присваивание запрещены.

Перемещение передаёт адрес получателю и оставляет источник пустым. Перемещающее присваивание освобождает прежний ресурс получателя. Самоприсваивание перемещением сохраняет ресурс.

Для одиночных объектов поддержаны преобразующие перемещение и присваивание `UniquePtr<U>` → `UniquePtr<T>` с проверками типов, описанными ниже. Преобразующее перемещение между специализациями массивов не реализовано.

### Операции

| Метод | Результат |
|---|---|
| `get()` | Возвращает адрес без передачи владения |
| `operator*`, `operator->` | Дают доступ к одиночному объекту |
| `operator[]` | Возвращает ссылку на элемент массива |
| `release()` | Возвращает адрес и опустошает владельца, не удаляя ресурс |
| `reset()` или `reset(nullptr)` | Опустошает владельца и удаляет прежний ресурс |
| `reset(newPtr)` | Принимает новый ресурс и удаляет прежний |
| `swap(other)` | Обменивает адреса между владельцами одного типа |
| `explicit operator bool()` | Проверяет наличие адреса |

`reset(get())` ничего не меняет. После `release()` вызывающий код обязан передать владение дальше либо самостоятельно вызвать `delete` или `delete[]`.

## SharedPtr

### Создание и владение

Внутреннее состояние — указатель на общий блок. Блок содержит `T*` и атомарный счётчик владельцев `std::atomic<std::size_t>`.

Непустой конструктор создаёт блок со счётчиком 1. Пустой указатель блока не имеет: его `use_count()` равен 0, в том числе после создания из типизированного нулевого указателя.

Копирование разделяет существующий блок и увеличивает счётчик. Перемещение передаёт блок без увеличения счётчика и опустошает источник. Уничтожение владельца уменьшает счётчик; переход к нулю удаляет объект или массив, затем сам блок.

Присваивание освобождает прежнюю долю владения получателя. Копирующее и перемещающее самоприсваивание сохраняют владение. Преобразования между разными типами `SharedPtr` не реализованы.

### Операции

| Метод | Результат |
|---|---|
| `get()` | Возвращает адрес объекта из блока либо `nullptr` |
| `operator*`, `operator->` | Дают доступ к одиночному объекту |
| `operator[]` | Возвращает ссылку на элемент массива |
| `use_count()` | Возвращает текущее значение счётчика, для пустого владельца — 0 |
| `reset()` или `reset(nullptr)` | Освобождает свою долю владения и опустошает указатель |
| `reset(newPtr)` | Создаёт новый блок владения и освобождает прежнюю долю |
| `swap(other)` | Обменивает блоки между владельцами одного типа |
| `explicit operator bool()` | Проверяет наличие объекта |

`reset(get())` ничего не меняет, в том числе при нескольких владельцах. Метода `release()` нет: отдельный владелец не может забрать ресурс у остальных. Внутренний `releaseOwnership()` уменьшает счётчик и выполняет удаление при достижении нуля.

### Потоки и циклы

Разные экземпляры, разделяющие один блок, можно копировать и уничтожать параллельно. Изменение одного экземпляра и доступ к самому объекту требуют отдельной синхронизации. Счётчик использует стандартный последовательный порядок атомарных операций.

`use_count()` — наблюдение за счётчиком, а не средство синхронизации доступа к объекту. Результат может измениться сразу после чтения.

`WeakPtr` отсутствует. Циклы совместного владения автоматически не освобождаются и должны разрываться вызывающим кодом.

## Проверки типов и наследование

Проверки выполняются через `static_assert` внутри шаблонных конструкторов, `reset()` и преобразующего перемещения `UniquePtr`.

| Сценарий | Условие |
|---|---|
| Приём `U*` владельцем одиночного `T` | `U` не массив и `U*` преобразуется в `T*` |
| Типы `U` и `T` различаются без учёта `const` и `volatile` | У `T` требуется виртуальный деструктор |
| Добавление `const`, например `int*` → `const int*` | Разрешено без виртуального деструктора |
| Приём массива | `U(*)[]` преобразуется в `T(*)[]` |
| `Derived[]` → `Base[]` | Запрещено даже при виртуальном деструкторе |

Если адрес заранее приведён к `Base*`, исходный тип восстановить невозможно. Вызывающий код отвечает за корректность удаления через этот базовый тип. Исходный адрес производного объекта и отдельная функция удаления не сохраняются.

Проверки находятся в телах функций, а не в `requires`. Поэтому `std::is_constructible`, `std::is_assignable` и проверка наличия выражения могут считать операцию доступной; ошибка обнаруживается при инстанцировании её тела.

## Сравнение и константность

Равенство владельцев одного типа сравнивает адреса из `get()`. Поддержаны сравнения с `nullptr`. Обратные сравнения и `!=` доступны благодаря правилам C++20 для `operator==`.

Константность самого владельца запрещает менять его состояние, но не делает объект константным: `const UniquePtr<int>` даёт доступ к изменяемому `int`. Для запрета изменения объекта нужен `UniquePtr<const int>`; такое же правило действует для `SharedPtr` и массивов.

## Гарантии при исключениях

- Операции `UniquePtr` объявлены `noexcept`; выделение самого объекта происходит в вызывающем коде до передачи адреса.
- `SharedPtr` выделяет память для общего блока. При ошибке его создания переданный объект или массив удаляется, исключение передаётся вызывающему коду.
- Неудачный `SharedPtr::reset(newPtr)` сохраняет прежний ресурс и счётчик, удаляя новый ресурс.
- Копирование и перемещение существующих `SharedPtr` память не выделяют и объявлены `noexcept`. Обнуление через `reset()` также не выделяет память.
- Присваивание сначала создаёт временного владельца, затем обменивает состояния. Поэтому допустим источник внутри прежнего объекта: `root = std::move(root->child)`; для `SharedPtr` допустимо и `root = root->child` при совместимых типах.
- Исключение из деструктора управляемого объекта не поддерживается и может привести к `std::terminate`.

## Сложность

Ниже не учитываются стоимость выделения памяти, работа деструкторов и конкуренция потоков за атомарный счётчик.

| Операция | Сложность |
|---|---|
| Доступ, сравнение, `swap`, перемещение в конструкторе, `release`, `use_count` | `O(1)` |
| Копирование `SharedPtr` | `O(1)` |
| Присваивание, `reset`, уничтожение владельца | `O(1)` служебной работы плюс удаление освобождаемого ресурса |

Удаление массива из `n` элементов вызывает `n` деструкторов. Удаление объекта может также уничтожить принадлежащие ему объекты. `UniquePtr` хранит одно поле-указатель; `SharedPtr` — одно поле-указатель и один общий блок на группу владельцев.
