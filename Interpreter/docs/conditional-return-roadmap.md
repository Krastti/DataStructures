# План добавления `return` в ветвях функций MiniLang

Добавить возможность возвращать значение прямо из ветвей `when` и `otherwise` внутри функции. Такой `return` завершает текущий вызов функции сразу после вычисления выражения. Возможность запланирована к реализации.

```minilang
function abs(n) ->
  when n < 0
    return 0 - n
  otherwise
    return n
  end
end

print abs(0 - 5)
print abs(3)
```

Ожидаемый вывод после реализации.

```text
5.0
3.0
```

## Предлагаемые правила

- `return выражение` допустим в теле функции и в её вложенных ветвях `when` и `otherwise`. Возврат завершает текущий вызов функции, в том числе при нескольких уровнях вложенности.
- Выражение вычисляется один раз в текущем окружении. Возвращаемое значение может быть числом, строкой или логическим значением.
- После выполненного `return` последующие инструкции функции пропускаются. Если возврат находится в ветви внутри цикла, он завершает также выполнение этого цикла и выходит из функции.
- Сохраняются короткая форма функции и многострочная форма с завершающим `return` после ветвления. Например, функция может вернуть значение в `when`, а для остальных случаев использовать общий итоговый `return`.
- Многострочная функция может завершаться блоком `when … otherwise … end`, если выбранная ветвь возвращает значение. Итоговый `return` непосредственно перед `end` функции становится необязательным.
- Если выполнение достигло конца функции без возврата значения, возникает ошибка выполнения с именем функции. Это правило проверяется на фактически выполненном пути.
- `return` требует выражения. Использование вне функции вызывает ошибку разбора. Вложенные объявления функций подчиняются действующим ограничениям языка.

## Этапы реализации

### Этап 1. Уточнить дизайн и спецификацию

- [ ] **1.1. Обновить дизайн.** По `TEMPLATE.md` описать инструкцию возврата, её связь с вызовом функции и прохождение результата через вложенные блоки. Дополнить архитектуру и функциональные требования.
- [ ] **1.2. Обновить грамматику.** Разрешить `return выражение` в контексте тела функции, включая вложенные блоки. Уточнить завершение многострочной функции без обязательного итогового `return`.
- [ ] **1.3. Зафиксировать семантику.** Описать ранний выход, продолжение после невыполненной ветви, отсутствие возврата на выбранном пути и ошибки вычисления возвращаемого выражения.
- [ ] **1.4. Выбрать представление.** Определить узел `ast::Return` и передачу результата текущего вызова. Предусмотреть совместимость существующих конструкторов AST, короткой формы и функций с отдельным выражением результата.

Критерий готовности — согласованы грамматика, поведение возврата, диагностика и совместимость существующих функций.

### Этап 2. Добавить разбор инструкции возврата

- [ ] **2.1. Расширить AST и посетителей.** Добавить узел возврата с выражением и обработку через `StatementVisitor`.
- [ ] **2.2. Передавать контекст функции.** При разборе вложенных блоков сохранять сведения о том, что они находятся внутри функции. За пределами функции отклонять `return`.
- [ ] **2.3. Обновить разбор многострочной формы.** Читать тело до `end` функции, учитывая `end` вложенных ветвлений и циклов. Допустить несколько возвратов в разных ветвях и инструкции после условного возврата.
- [ ] **2.4. Добавить тесты парсера.** Покрыть пример `abs`, вложенные `when`, ветвь без `otherwise`, итоговый возврат после ветвления, пустое выражение и `return` вне функции. Проверить прежние формы объявления и освобождение частичного AST при ошибке.

Критерий готовности — парсер строит AST с возвратами в ветвях и сохраняет прежние допустимые программы.

### Этап 3. Реализовать ранний выход из функции

- [ ] **3.1. Вычислить возвращаемое значение.** Обработать `ast::Return`, вычислять выражение один раз и сохранять результат для текущего вызова.
- [ ] **3.2. Передать завершение через блоки.** Прекращать обход инструкций после возврата. Вложенные ветви и циклы должны передавать завершение до границы текущей функции.
- [ ] **3.3. Изолировать вызовы.** Рекурсивный или вложенный вызов получает собственное состояние возврата. Возврат из вызываемой функции позволяет продолжить вычисление выражения вызывающей функции.
- [ ] **3.4. Освободить области видимости.** При возврате снимать активные области циклов и кадр функции. Ошибки выражения возврата должны проходить через существующую обработку исключений с сохранением записанного вывода.
- [ ] **3.5. Проверить исполнение.** Покрыть обе ветви, вложенные условия, выход из ветви внутри цикла, рекурсию, строки и логические значения. Через изменение переменных и вывод проверить пропуск инструкций после возврата. Проверить ошибку достижения конца функции и повторный запуск после ошибки.

Критерий готовности — функция возвращает значение с любой поддерживаемой глубины вложенности, состояния вызовов и областей видимости корректно освобождаются.

### Этап 4. Поддержать библиотеки, CLI и GUI

- [ ] **4.1. Проверить библиотеки.** Загрузить через `using` функцию с возвратами в ветвях и вызвать её из основной программы. В CLI проверить результат, диагностику и накопленный вывод при ошибке.
- [ ] **4.2. Обновить представления GUI.** Показывать `Return` и его выражение в деревьях инструкций, выражений и диаграмме AST.
- [ ] **4.3. Согласовать трассу.** В обычном и пошаговом режимах показывать вычисление возвращаемого выражения и завершение вызова. События вложенных блоков должны сохранять правильную вложенность трассы при раннем выходе.
- [ ] **4.4. Проверить управление выполнением.** Пройти возврат из библиотеки по шагам, остановить выполнение перед возвратом и повторить запуск после ошибки вычисления результата.

Критерий готовности — библиотечные функции с условным возвратом работают в CLI и отображаются в обычном и пошаговом режимах GUI.

- [ ] **5.2. Согласовать документы.** Обновить дизайн, спецификацию и архитектуру, включая правила отсутствующего результата и прохождение возврата через вложенные блоки.

- [ ] **5.4. Зафиксировать результаты.** Отметить завершённые работы и записать фактические результаты сборки, тестов и проверки GUI, включая пропущенные сценарии.

Критерий готовности — примеры воспроизводятся, документация соответствует поведению, проверки пройдены и результаты записаны.
