# Как расширять MiniLang

Разберём добавление оператора `%` для вычисления остатка от деления. Пример описывает будущую доработку.

## 1. Определите поведение

В этом примере `%` принимает два числа, имеет тот же приоритет, что `*` и `/`, и группируется слева направо. Остаток вычисляется по правилам `std::fmod`. Нулевой делитель вызывает ошибку выполнения по тому же правилу, что при `/`.

```minilang
remember x = 17 % 5
print x
print 2 + 17 % 5 * 3
```

Ожидаемый вывод:

```text
2.0
8.0
```

Во второй строке вывода сначала вычисляется `17 % 5`, затем результат умножается на `3` и прибавляется к `2`.

## 2. Передайте оператор от исходного текста до результата

| Где | Что изменить |
|---|---|
| [`token.h`](../headers/token.h) | Добавить `TokenType::Percent`. |
| [`lexer.cpp`](../sources/lexer.cpp) | Распознать `%` в `scanToken` и вернуть токен `Percent` с лексемой `%`. |
| [`parser.cpp`](../sources/parser.cpp) | В `parseMultiplication` добавить `Percent` к списку операторов `parseBinaryChain`. |
| [`interpreter.cpp`](../sources/interpreter.cpp) | В `applyNumericOperation` обработать `Percent`. Сначала проверить `right == 0.0`, затем вернуть `std::fmod(left, right)` из `<cmath>`. |

Для `%` подходит существующий `ast::Binary`. Парсер собирает его через `ExpressionTree::makeBinary`, а `Binary::accept` вызывает `Interpreter::visit(const ast::Binary&)`. Обработчик уже вычисляет оба операнда и проверяет их типы. Новый `visit` понадобится при добавлении нового типа узла.

```text
символ % → токен Percent → дерево Binary(Percent, слева, справа)
         → Binary::accept → Interpreter::visit(Binary) → applyNumericOperation
```

## 3. Проверьте каждый уровень

- **Лексер.** Для `17%5` проверьте последовательность `Number`, `Percent`, `Number`, `EndOfFile` с исходными лексемами.
- **Парсер.** У `2 + 17 % 5 * 3` корень `+`, правая ветвь `*`, а левый операнд `*` содержит `%`. Для `17 %` проверьте ошибку о пропущенном операнде.
- **Исполнитель.** Проверьте результат примера, левую ассоциативность (`20 % 6 % 3` даёт `2.0`), дробное значение (`(7 / 2) % 2` даёт `1.5`) и ошибки для `5 % 0` и `"text" % 2`.
- **CLI.** Запустите пример из `.mini`. Проверьте код `0` и ожидаемый `stdout`. Для `print 5 % 0` проверьте код `1` и диагностику в `stderr`.

Тесты добавляйте в [`Interpreter/tests/`](../tests/). При добавлении нового файла тестов подключите его к `UnitTests` в [`../../CMakeLists.txt`](../../CMakeLists.txt). Команды сборки и запуска тестов приведены в [документации CLI](cli.md). После реализации обновите [спецификацию](specification.md) и [архитектуру](architecture.md), если изменились контракты компонентов.

## Если меняется грамматика или нужен новый узел

Например, для новой инструкции `assert выражение` сначала опишите её синтаксис и поведение при `true`, `false` и значении другого типа. Затем добавьте ключевое слово в лексер, узел в `statements.h` и ветку в `parseStatement`. Узел хранит выражение в `ExpressionTree`, а `parseStatement` возвращает его вместе с `nextPosition` в `ParsedStatement`. Программа по-прежнему представляет собой массив инструкций.

Добавьте `visit(const Assert&)` в `StatementVisitor` и определите `Assert::accept` в `ast.cpp` по образцу `Print`. В обработчике интерпретатора вызовите `evaluate` для корня выражения и проверьте возвращённый `Value`. Обновите остальные реализации `StatementVisitor`, включая посетителей в тестах. Для нового вида выражения используйте тот же порядок с `ExprVisitor` и подходящим уровнем парсера.
