# План добавления перегрузки функций MiniLang

Перегрузка по количеству параметров позволяет объявить несколько функций с одним именем и выбирать объявление по числу аргументов вызова. Возможность запланирована к реализации.

```minilang
function sum(a, b) -> a + b end
function sum(a, b, c) -> a + b + c end

print sum(2, 3)
print sum(2, 3, 4)
```

Ожидаемый вывод после реализации.

```text
5.0
9.0
```

## Правила первой версии

- Сигнатура определяется именем и количеством параметров. Объявления `sum(a, b)` и `sum(a, b, c)` образуют разные перегрузки.
- Повтор одной сигнатуры вызывает ошибку выполнения. Например, `sum(a, b)` и `sum(x, y)` конфликтуют. Имена параметров служат для связывания аргументов внутри выбранной функции.
- Для вызова выбирается точное совпадение имени и количества аргументов. Нулевая перегрузка допускается на общих основаниях.
- Выбор определяется количеством аргументов, записанных в AST вызова. После успешного выбора аргументы вычисляются один раз слева направо, затем создаётся кадр с параметрами выбранного объявления.
- Неизвестное имя и отсутствие перегрузки с требуемым количеством аргументов дают отдельные ошибки. При ошибке выбора выражения аргументов не вычисляются.
- Объявление регистрируется при его выполнении. Доступность перегрузок зависит от порядка выполнения, включая вызовы из тела другой функции.
- Функции библиотек и основного файла участвуют в общей таблице. Одинаковое имя с разным количеством параметров допускается между файлами, совпадение всей сигнатуры вызывает ошибку.
- Повторное подключение одного канонического пути через `using` сохраняет действующее правило загрузки файла один раз.

## Этапы реализации

Этапы выполняются последовательно. Проверки добавляются вместе с изменяемым поведением, отметки готовности заполняются по фактическому результату.

### Этап 1. Уточнить дизайн и спецификацию

- [ ] **1.1. Дополнить дизайн.** По `TEMPLATE.md` описать сигнатуру, набор перегрузок и выбор объявления при вызове. Обновить связи сущностей и функциональные требования интерпретатора.
- [ ] **1.2. Зафиксировать семантику.** В спецификации описать правила первой версии, нулевую перегрузку, момент регистрации, рекурсию и конфликты между библиотеками и основным файлом.
- [ ] **1.3. Определить диагностику.** Для повторного объявления указывать имя и количество параметров. Для отсутствующей перегрузки показывать имя, переданное число аргументов и доступные количества параметров по возрастанию.
- [ ] **1.4. Определить хранение.** Предусмотреть собственную таблицу `Map<std::string, Map<std::size_t, const ast::Function*>>`. Таблица принадлежит одному выполнению, узлы функций принадлежат AST. Подтвердить возможность регистрации и поиска без копирования AST.

Критерий готовности — дизайн и спецификация согласованы, определены сигнатура, правила выбора, диагностика и владение данными.

### Этап 2. Изменить регистрацию функций

- [ ] **2.1. Обновить таблицу исполнителя.** Заменить единственное объявление по имени набором перегрузок, индексируемым количеством параметров. Сохранить новое пустое состояние таблицы на каждый `Interpreter::execute`.
- [ ] **2.2. Зарегистрировать сигнатуру.** В посетителе `ast::Function` создавать набор для нового имени и добавлять объявление по количеству параметров. До изменения существующего набора проверять конфликт сигнатуры.
- [ ] **2.3. Проверить регистрацию.** Покрыть несколько перегрузок, одинаковую сигнатуру с разными именами параметров, конфликт после успешной регистрации других функций и повторный запуск после ошибки.

Критерий готовности — таблица хранит несколько объявлений одного имени, повторная сигнатура отклоняется, независимость запусков сохраняется.

### Этап 3. Добавить выбор перегрузки при вызове

- [ ] **3.1. Найти объявление.** В посетителе `ast::Call` сначала искать имя, затем точное количество аргументов. Формировать согласованную диагностику для обоих случаев отсутствия.
- [ ] **3.2. Выполнить выбранную функцию.** Использовать её параметры, тело и выражение результата. Сохранить однократное вычисление аргументов слева направо, отдельный кадр вызова, события наблюдателя и очистку при исключении.
- [ ] **3.3. Проверить выбор.** Покрыть ноль, один и несколько аргументов, вложенные вызовы и рекурсивные обращения к своей и другой перегрузке. Проверить выбор среди уже зарегистрированных объявлений.
- [ ] **3.4. Проверить побочные эффекты.** Через аргументы с `++` и `--` подтвердить порядок и однократность вычисления. При отсутствующей сигнатуре подтвердить сохранность переменных и отсутствие событий вычисления аргументов.
- [ ] **3.5. Проверить значения.** Передать и вернуть числа, строки и логические значения через подходящие функции. Подтвердить, что выбор определяется именем и числом аргументов.

Критерий готовности — вызовы выбирают нужное объявление, ошибки выбора возникают до вычисления аргументов, кадры и трасса соответствуют выбранной перегрузке.

### Этап 4. Проверить библиотеки, CLI и GUI

- [ ] **4.1. Проверить `using`.** Подключить две библиотеки с разными перегрузками одного имени, затем добавить перегрузку в основной программе. Проверить повторное подключение общей зависимости и конфликт одной сигнатуры в разных файлах.
- [ ] **4.2. Добавить сквозные проверки CLI.** Проверить вывод программы с перегрузками, код завершения и диагностику повторной или отсутствующей сигнатуры. При ошибке выполнения сверить уже накопленный вывод.
- [ ] **4.3. Проверить представления GUI.** Убедиться, что отдельные объявления одного имени различимы по параметрам в AST, а шаги вызова связаны с выбранным объявлением. При необходимости дополнить подписи количеством параметров.
- [ ] **4.4. Проверить восстановление.** После ошибки внутри перегрузки повторить запуск и убедиться, что кадры, таблица функций и наблюдатель корректно освобождены или сброшены.

Критерий готовности — функции из разных исходников следуют единым правилам, CLI и GUI корректно выполняют и отображают вызовы перегрузок. Проверки через подключение библиотек в GUI выполняются после интеграции загрузчика по плану `using`.

### Этап 5. Обновить документацию и выполнить итоговые проверки

- [ ] **5.1. Описать архитектуру.** Обновить устройство таблицы функций, порядок регистрации, выбор по сигнатуре и время жизни ссылок на AST.
- [ ] **5.2. Согласовать документацию библиотек.** В дизайне загрузчика, спецификации и плане `using` уточнить правило конфликта объявлений через полную сигнатуру.
- [ ] **5.3. Добавить пример.** Подготовить пример с двумя перегрузками и ожидаемым выводом, включить его в документацию MiniLang.
- [ ] **5.4. Выполнить сборку и тесты.** Собрать Release с `BUILD_GUI=ON` в `/tmp/ds-build`, запустить полный CTest. Проверить освобождение таблиц и кадров при успехе и ошибках, включая проверки MiniLang с AddressSanitizer и UndefinedBehaviorSanitizer.
- [ ] **5.5. Записать результат.** Отметить завершённые подэтапы, фактические результаты сборки и тестов, а также пропущенные проверки.

Критерий готовности — пример работает через обычные точки входа, проверки пройдены, документация описывает реализованное поведение.
