# План добавления `using` в MiniLang

Директива `using` подключает файл с функциями на MiniLang. Например, основной файл содержит:

```minilang
using "lib/math.mini"

print square(5)
```

Файл `lib/math.mini` объявляет функцию:

```minilang
function square(x) -> x * x end
```

Программа выводит `25.0`.

## Правила первой версии

- `using` — ключевое слово. Директива занимает отдельную строку в начале файла. После `using` указывается непустой путь в двойных кавычках. Разбор пути использует существующие правила строковых литералов.
- Относительный путь отсчитывается от каталога файла с директивой. Например, `lib/math.mini` может подключить соседний `constants.mini` через `using "constants.mini"`.
- В библиотеке разрешены директивы `using` и объявления функций верхнего уровня. Зависимости загружаются перед объявлениями подключающей их библиотеки. Директивы одного файла обрабатываются сверху вниз.
- Один и тот же файл подключается один раз за запуск. Пути сравниваются после канонизации. Если очередной путь уже есть в текущей цепочке загрузки, сообщить об ошибке и вывести цепочку, например `a.mini → b.mini → a.mini`.
- Объявления всех библиотек и основной программы попадают в общую таблицу функций. Повторное объявление имени обрабатывается по действующему правилу интерпретатора.

## Этапы реализации

Этапы выполняются последовательно. Проверки каждого компонента добавляются вместе с его реализацией. Отметки готовности заполняются после выполнения соответствующих работ.

- [x] **1.3. Определить результат разбора файла.** Предусмотреть отдельные списки подключений и инструкций. Сохранить возможность разбора и выполнения обычных программ без `using` через существующие точки входа.

Критерий готовности — дизайн и спецификация описывают одинаковое поведение, определены входные данные загрузчика и результат разбора файла.

Этап завершён на уровне проектирования. Правила и контракты записаны в [дизайне](design.md) и [спецификации](specification.md#подключение-библиотек-через-using--проектируемое-расширение).

- [x] **2.4. Проверить содержимое библиотеки.** После разбора разрешать на верхнем уровне библиотеки объявления функций. Выдавать ошибку для остальных инструкций.

Release-сборка с `BUILD_GUI=ON` прошла, CTest — 280 из 280 тестов, включая 125 проверок с меткой `Interpreter`. Интерактивная проверка GUI и проверки с санитайзерами в этом этапе не выполнялись.

- [ ] **3.3. Обойти зависимости.** Загружать их в глубину в порядке директив. Хранить активную цепочку отдельно от успешно загруженных файлов. Сначала проверять цикл, затем повторное подключение.
- [ ] **3.4. Собрать программу.** Перемещать AST зависимостей перед объявлениями подключающей библиотеки, затем добавлять инструкции основной программы. Сохранять владение узлами до завершения исполнения и работы с ними в GUI.

- [ ] **3.6. Проверить загрузчик.** Покрыть вложенные зависимости, повторные пути, цикл, ошибки файлов и освобождение ресурсов после незавершённой загрузки.

Критерий готовности — загрузчик возвращает общий AST после успешного разбора всех файлов, а при ошибке сообщает путь и цепочку подключений. Выполнение начинается после завершения загрузки.

## Проверки

- Лексер и парсер. Распознавание `using` и обычного идентификатора `usingValue`, путь с пробелами, путь перед концом файла, отсутствующий или пустой аргумент, лишние токены после пути, директива внутри блока или после инструкции.
- Загрузчик и CLI. Вызов функции из библиотеки, загрузка вложенной зависимости относительно её файла, повторное подключение через разные пути, циклическая зависимость, отсутствие файла и ошибка разбора в библиотеке. Проверить отклонение исполняемой инструкции верхнего уровня библиотеки и повторного объявления функции.
- GUI. Относительный путь при запуске открытого файла и текста с выбранным каталогом. Отображение ошибки загрузки и пошаговый вход в функцию из библиотеки.
