# Теория лабораторной работы № 2 и подготовка к защите

В ЛР-2 решаются две задачи. Алфавитный указатель находит страницы текста по написанию слова. Индексы записей о людях поддерживают точный поиск по трём полям и выборку по диапазону годов рождения. В первой задаче сравниваются бинарный поиск и поиск в красно-чёрном дереве. Во второй сравниваются поиск по дереву годов и полный просмотр исходных записей.

## 1. Что полезно сказать в начале защиты

> Индекс — вспомогательная структура данных, которая организует поиск записей или их местоположений по ключу. Я построил алфавитный указатель, где ключ — слово, а результат — номера страниц. Для записей о людях я построил два индекса. Составной ключ из имени, фамилии и года нужен для точных совпадений, а отдельный ключ по году — для запросов по диапазону. Оба вида данных обрабатываются на одних и тех же реализациях упорядоченного словаря. Для каждой задачи я проверяю совпадение результатов разных способов поиска и измеряю время.

В задании это варианты И-4 и И-5. Для И-4 размер страницы задаётся в символах и учитывается разбиение на строки. Для И-5 реализованы диапазоны значений и составной атрибут. В перечне методов используются М-2 (бинарный поиск) и М-3 с М-3.1 (сбалансированное двоичное дерево). По таблицам задания соответствующие позиции дают 17 + 19 + 10 + 22 = 68 баллов рейтинга сложности. Рейтинг используется при оценивании работы. [Задание ЛР-2](ЛР-2.pdf)

## 2. Основные понятия

| Понятие | Определение и пример |
|---|---|
| Запись | Один объект данных. В ЛР-2 это сведения об одном человеке. |
| Атрибут | Поле или свойство объекта. Примеры — имя, год рождения, написание слова, номер страницы. |
| Ключ поиска | Значение, по которому ищут. Это может быть один атрибут или кортеж из нескольких атрибутов. Один ключ может соответствовать нескольким исходным записям. |
| Индекс | Вспомогательная структура, по которой ключ ведёт к связанным записям или их местоположениям. Указатель на текст хранит номера страниц, а `PersonIndex` хранит копии записей в группах. |
| Словарь `Map` | Тип данных, который связывает каждый ключ с одним значением и поддерживает операции по ключу. Значением может быть массив. В проекте `Map<Key, Data>` — псевдоним `RedBlackTree<Key, Data>`. |
| Упорядоченный словарь | Словарь с порядком ключей. Этот порядок позволяет обходить ключи по возрастанию и выбирать непрерывный диапазон ключей. |
| Полный просмотр | Проверка условия на каждой исходной записи. Сортировка и подготовка индекса для него не нужны. |
| Точный поиск | Поиск по равенству ключа. В составном ключе должны совпасть все компоненты. |
| Поиск по диапазону | Выборка ключей между двумя границами. В ЛР-2 обе границы включаются. |

`Map` описывает доступные операции и представление в проекте. Слово «индекс» описывает роль структуры по отношению к исходным данным. Например, `birthYearIndex` — это словарь «год → массив записей», который служит индексом по году. Индекс можно реализовать и через отсортированный массив, хеш-таблицу или другое дерево. ### Сущности и атрибуты в дизайне

В пункте 2 диаграмма описывает типы объектов предметной области и связи экземпляров. Название узла вроде «Страница» обозначает тип, а страница № 3 конкретного текста — экземпляр. Для такого типа можно спроектировать класс, но в реализации его экземпляры могут храниться и проще. В ЛР-2 многие из них представлены элементами массивов.

| Тип объекта | Пример экземпляра и его роль |
|---|---|
| Текст | Один документ, который состоит из исходных строк и делится на страницы. |
| Строка | Вторая строка документа. Граница строк влияет на разделитель внутри страницы. |
| Страница | Третья страница этого текста. Указатель ведёт к ней по её номеру. |
| Вхождение слова | Второе появление слова `кот` в исходной строке. Оно связано со строкой и после разбиения попадает на страницу. |
| Набор записей | Конкретная коллекция, по которой строятся индексы и выполняется полный просмотр. |
| Запись о человеке | Одна запись в этом наборе со своими значениями полей. |
| Индекс | Общее понятие для двух видов поисковых указателей. |
| Алфавитный указатель | Построенный указатель по конкретному тексту, связывающий написания со страницами. |
| Индекс записей | Индекс, построенный по конкретному набору записей и связывающий ключи с результатами. |

Написание слова, номер страницы, имя, фамилия и год — атрибуты. Точный поиск и поиск по диапазону — операции. `Индекс` в диаграмме объединяет две задачи по назначению. Публичный базовый класс для `AlphabeticalIndex` и `PersonIndex` коду для этого не требуется.

**Как объяснить вхождение на защите.** Два появления слова `кот` можно различить по позиции, и при разбиении они могут попасть на разные страницы. Поэтому модель связывает каждое вхождение с исходной строкой и страницей. В коде вхождение представлено позицией в `words`, а по тому же индексу в `beginsLine` хранится признак начала исходной строки. Страница вычисляется при обработке. При желании эти данные можно было бы объединить в `struct WordOccurrence`. [Дизайн](design.md) · [Разбиение текста в коде](../source/AlphabeticalIndex.cpp)

## 3. Алфавитный указатель

### Вход, выход и правила разбиения

Вход — строки текста и размер обычной страницы `P`. Выход — содержимое страниц и записи «слово → номера страниц». Номер страницы начинается с 1. Позиция в массиве начинается с 0, поэтому страница `n` лежит в `pages()[n - 1]`.

| Страница | Лимит |
|---|---:|
| Первая | ⌊P/2⌋ |
| Каждая десятая | ⌊3P/4⌋ |
| Остальные | P |

Слова размещаются целиком и в порядке появления. На пустой странице перед первым словом разделитель не нужен. Если на странице уже есть текст, перед новым словом ставится один знак. Это перенос, если слово начинало исходную строку, и пробел в остальных случаях. Таким образом, для группы из `n` слов требуемое место равно сумме длин слов плюс `n - 1`. Если целое слово не помещается, программа переходит дальше и заново вычисляет лимит. Пустая уменьшенная страница сохраняет свой номер.

В реализации слова выделяются по пробельным разделителям потока. Повторные разделители сворачиваются, а пустые строки не создают слов. Регистр и пунктуация сохраняются. Для корректного UTF-8 длина считается в кодовых точках. Например, `кот` занимает 6 байтов, но 3 кодовые точки. Один видимый знак может состоять из нескольких кодовых точек, например буква с комбинируемым ударением. Порядок ключей задаёт сравнение строк C++ и стандартная для него лексикографическая последовательность. Словарные правила конкретного языка отдельно не применяются.

При `P < 2` или слове длиннее `P` выбрасывается `std::invalid_argument`. Пустой текст даёт пустой указатель и одну пустую страницу. Слово длиной ровно с текущий лимит помещается на пустой странице, а на непустой ему ещё потребуется место для разделителя. [Построение указателя](../source/AlphabeticalIndex.cpp)

### Пример построения вручную

Входные строки — `кот мир` и `дом кот`. Пусть `P = 8`.

| Шаг | Слово | Решение |
|---|---|---|
| 1 | кот | На странице 1 лимит 4. Слово занимает 3. |
| 2 | мир | На странице 1 остался 1 символ, а нужно 4 с пробелом. На странице 2 слово занимает 3. |
| 3 | дом | Это начало второй исходной строки. Перенос и слово занимают 4, поэтому на странице 2 занято 7 из 8. |
| 4 | кот | С пробелом нужно 4, а осталось 1. Слово переходит на страницу 3. |

Страницы получаются `кот`, `мир\nдом` и `кот`. Записи указателя — `дом → [2]`, `кот → [1, 3]`, `мир → [2]`. Если два вхождения одного слова попали на одну страницу, в списке остаётся один номер.

### Откуда берутся дерево и массив

1. Для каждого слова определяется номер страницы. Программа ищет ключ в дереве и создаёт пустой список, если ключ встречен впервые.
2. В список добавляется номер страницы, если список пуст или номер отличается от последнего. Обработка идёт по порядку, поэтому номера для любого слова не убывают. Если текущий номер уже встречался, он обязательно последний.
3. Симметричный обход дерева выдаёт записи в порядке ключей. Эти записи копируются в массив `orderedEntries`. По нему можно вывести указатель или выполнить бинарный поиск. Дерево сохраняется для второго способа поиска.

Для статического текста возможен вариант с сортировкой всех пар «слово, страница» и группировкой. Дерево удобно при накоплении по мере чтения, поскольку каждый новый ключ вставляется без сдвига массива. В ЛР-2 сохранение дерева также позволяет сравнить два способа поиска по одним данным.

### Интерфейс `AlphabeticalIndex`

| Метод | Смысл |
|---|---|
| `build(lines, pageSize)` | Статическая функция, которая создаёт указатель и страницы из входных строк. |
| `findBinary(word)` | Ищет в отсортированном массиве и возвращает копию списка страниц. |
| `findTree(word)` | Ищет в дереве и возвращает копию списка страниц. |
| `containsBinary(word)` | Проверяет, пуст ли результат `findBinary`. В текущей реализации при успехе список страниц копируется. |
| `entries()` | Даёт константную ссылку на все отсортированные записи `AlphabeticalEntry`. |
| `pages()` | Даёт константную ссылку на массив содержимого страниц. |

Отсутствующее слово даёт пустой массив. Поля индекса закрыты. `UniquePtr` владеет деревом, `orderedEntries` хранит отсортированные записи, `pageContents` — содержимое страниц. Константные ссылки из `entries()` и `pages()` используют при живом объекте индекса. `const` после скобок позволяет вызвать методы на константном объекте, а `[[nodiscard]]` просит выдать диагностику при игнорировании результата. ## 4. Бинарный поиск и красно-чёрное дерево

### Бинарный поиск по массиву

В реализации поддерживается полуинтервал `[first, last)`. Начальные границы — 0 и размер массива. На каждом шаге вычисляется `middle = first + (last - first) / 2`. Если слово в середине меньше запроса, `first` переносится за середину. Иначе `last` становится серединой. В результате `first` — позиция первого ключа, который не меньше запроса. Остаётся проверить, что позиция существует и слово совпало.

Например, в массиве `[дом, кот, лес, мир, сад]` для запроса `мир` первой проверяется запись `лес`. Затем берётся середина оставшейся правой части, `сад`. После сужения остаётся позиция `мир`. За один шаг длина интервала примерно делится пополам, поэтому требуется логарифмическое число шагов. Доступ к элементу массива по позиции занимает постоянное время. В связном списке поиск середины потребовал бы прохода по узлам. [Бинарный поиск в коде](../source/AlphabeticalIndex.cpp)

### Двоичное дерево поиска и балансировка

В двоичном дереве поиска ключи слева от узла меньше его ключа, а справа — больше. Поиск начинается с корня. Меньший запрос ведёт налево, больший — направо. При равенстве найдена группа. Пустая ветвь означает, что ключа нет. Время поиска пропорционально высоте дерева. Например, если корень — `кот`, запрос `мир` сразу отправляется вправо, хотя в отсортированном массиве первый шаг мог сравнивать с `лес`.

В обычном двоичном дереве последовательная вставка возрастающих ключей может построить цепочку высоты порядка числа ключей. Красно-чёрное дерево ограничивает высоту с помощью правил окраски.

1. Каждый узел красный или чёрный, корень чёрный.
2. Пустые потомки считаются чёрными листьями.
3. У красного узла дети чёрные. Два красных узла подряд на пути невозможны.
4. У всех путей от данного узла к пустым листьям одинаковое число чёрных узлов.

Отсюда следует, что между чёрными узлами на пути может быть максимум по одному красному. Если чёрная высота корня равна `b`, дерево содержит как минимум `2ᵇ − 1` внутренних узлов. Это получается индукцией по поддеревьям. При спуске в каждого ребёнка чёрная высота уменьшается максимум на один, поэтому минимальное число узлов растёт как в полном двоичном дереве. Тогда `b ≤ log₂(n + 1)`, а обычная высота не превышает `2b`.

Новый узел обычно вставляется красным, чтобы сохранить число чёрных узлов на путях. При чёрном родителе конфликт отсутствует. При красных родителе и дяде перекрашивают их и дедушку, затем продолжают проверку выше. При чёрном дяде повороты и перекрашивание исправляют положение. Если сначала образуется «угол», промежуточный поворот превращает его в «линию». В конце корень чёрный. Поворот меняет форму дерева локально и сохраняет порядок ключей при симметричном обходе. [Красно-чёрное дерево](../../FirstLab/headers/RedBlackTree.tpp)

### Что сравнивают на практике

| Свойство | Отсортированный массив | Красно-чёрное дерево |
|---|---|---|
| Поиск точного ключа | Середина текущего диапазона | Путь от корня по сравнениям |
| Худшее число сравнений | O(log n) | O(log n) |
| Вставка нового ключа | O(n) на сдвиг в худшем случае | O(log n) по узлам |
| Доступ к данным | Последовательный блок памяти для массива записей | Переходы по указателям между узлами |
| Диапазон | Найти начало бинарным поиском и идти по массиву | Обходить ключи в интервале, пропуская неподходящие ветви |

Упорядочивание сохраняется и при обходе по диапазону. Хеш-таблица — ещё один вариант для точного поиска. При благоприятном распределении она даёт в среднем постоянное число операций над ключом, но стандартный обход таблицы не выдаёт отсортированные ключи. Диапазон по году потребовал бы дополнительной организации или перебора. Для уже построенного статического индекса массив часто быстрее благодаря компактности. Фактическое время зависит от данных, стоимости сравнения и объёма возвращаемого результата.

AVL-дерево тоже обеспечивает логарифмическую высоту. Оно ограничивает разницу высот дочерних поддеревьев, а красно-чёрное дерево использует цвета и одинаковую чёрную высоту путей. Для больших дисковых индексов часто применяют B+-деревья, где узел содержит много ключей, а диапазон можно читать по соседним листьям.

## 5. Индексирование записей о людях

### Два индекса над одним набором

| Поле `PersonIndex` | Ключ | Значение |
|---|---|---|
| `compositeIndex` | `std::tuple<std::string, std::string, int>` из имени, фамилии и года | Массив записей с этим сочетанием полей |
| `birthYearIndex` | Целый год рождения | Массив записей с этим годом |

Ключ `std::tuple` сравнивается лексикографически. Сначала важно имя, при равенстве — фамилия, при равенстве первых двух полей — год. Поэтому диапазон по году в таком порядке может лежать в разных частях дерева. В дереве с ключом по году нужные годы образуют подряд идущий отрезок при симметричном обходе.

Метод `add` добавляет копию записи в обе группы. Один узел дерева соответствует уникальному ключу. Массив значений сохраняет все записи и их порядок добавления внутри группы, в том числе полностью одинаковые записи. `id` — поле результата и участвует при сверке, а точный индекс использует только имя, фамилию и год. Сравнение имён учитывает регистр. [Интерфейс](../include/PersonIndex.h) · [Добавление и точный поиск](../source/PersonIndex.cpp)

### Как устроен обход диапазона

1. Начинаем с корня и используем стек, чтобы отложить узлы, которые нужно обработать после левого поддерева.
2. Если год узла меньше нижней границы, идём вправо. Сам узел и всё левое поддерево уже исключены.
3. Если год узла не меньше нижней границы, помещаем узел в стек и спускаемся влево. Так следующим обрабатывается наименьший ещё не выданный ключ.
4. При извлечении узла из стека сравниваем его с верхней границей. Если год больше неё, обход завершается, поскольку следующие годы будут ещё больше. Иначе добавляем группу этого года и продолжаем с правого поддерева.

`Map::range` возвращает подходящие пары «год, группа». `PersonIndex::findBirthYearRange` собирает группы в один массив записей. Границы включаются. `[2002, 2002]` выбирает один год, а `[2005, 2000]` вызывает `std::invalid_argument`. Допустимый диапазон при пустом наборе или отсутствии совпадений даёт пустой результат. `all()` обходит весь индекс по году и возвращает все записи в порядке годов. [Обход `range`](../../FirstLab/headers/BinaryTree.tpp#L326) · [Сборка результата](../source/PersonIndex.cpp)

### Пример и сверка результатов

| ID | Имя | Фамилия | Год |
|---|---|---|---:|
| 1 | Анна | Иванова | 2002 |
| 2 | Иван | Петров | 2001 |
| 3 | Анна | Иванова | 2002 |
| 4 | Олег | Сидоров | 2002 |
| 5 | Анна | Иванова | 2005 |

- Точный запрос `(Анна, Иванова, 2002)` возвращает `[1, 3]`.
- Диапазон `[2001, 2002]` по индексу возвращает `[2, 1, 3, 4]`, потому что 2001 идёт первым.
- Полный просмотр для того же диапазона возвращает `[1, 2, 3, 4]`, потому что читает исходную коллекцию сверху вниз.

`samePersonRecords` проверяет совпадение состава выборок с учётом повторов. Сначала она сравнивает размеры. Затем для каждой записи строится временный кортеж `(id, имя, фамилия, год)`. Кортежи сортируются и сравниваются поэлементно. Имена в этих кортежах представлены `std::string_view`, поэтому создавать копии строк для сортировки не нужно. Исходный порядок обеих выборок сохраняется. Например, `[A, B, A]` и `[B, A, A]` совпадают, а `[A, B, A]` и `[A, B, B]` различаются.

Функция используется при сравнении диапазонных запросов в консоли и GUI, а также проверяется тестами. Сверка выполняется за пределами замера. В исходной коллекции консоль и GUI сохраняют порядок записей. Сортировка временных ключей нужна для проверки результата, а сортировка отдельных копий входа — для эксперимента с порядком построения. ## 6. Сложность и память

Пусть `W` — число всех вхождений слов, `D` — число различных слов, `N` — число записей о людях, `U` — число различных составных ключей, `Y` — число различных годов. `K` в строке таблицы — число элементов возвращаемого результата.

| Операция | Оценка | Откуда берётся |
|---|---|---|
| Заполнение дерева слов | O(W log(D + 1)) сравнений ключей при непустом тексте | На каждое вхождение приходится постоянное число поисков или вставок. Само чтение текста, сравнение строк и формирование страниц учитываются отдельно. |
| Получение массива из дерева слов | O(D) посещений узлов | Каждый узел обходится один раз. Дополнительно копируются слова и все списки страниц. |
| Поиск слова любым из двух методов | O(log(D + 1) + K) | Найти запись и скопировать K номеров страниц. Сравнение строк имеет собственную стоимость. |
| Построение `PersonIndex` | O(N(log(U + 1) + log(Y + 1))) сравнений для непустого набора | Каждая запись добавляется в два дерева. Плюс копирование записей и рост массивов групп. |
| Точный поиск записей | O(log(U + 1) + K) | Найти составной ключ и скопировать K записей. Сравнение имён и копирование строк считаются отдельно. |
| Диапазон по индексу, обход и однократная выдача записей | O(log(Y + 1) + K) | Обход посещает подходящие годы и узлы порядка высоты дерева на границах. В каждой подходящей группе есть хотя бы одна запись, поэтому число таких групп не превышает K. |
| Диапазон полным просмотром | O(N) | Проверяются все записи, а K записей копируются в ответ при K ≤ N. |
| Сверка двух выборок равного размера K | O(K log(K + 1)) сравнений, O(K) дополнительной памяти | Строятся и сортируются два массива кортежей. Имена сравниваются посимвольно при необходимости. |

В оценках времени манипуляции с записями считаются единичными, если стоимость строк не выделена отдельно. Копирование строки зависит от её длины. Для двух пустых индексов вызовы поиска и сравнения имеют постоянную стоимость. При широком диапазоне выдача почти всего набора сама требует O(N) работы.

Дерево при обходе диапазона использует стек размера O(log(Y + 1)). Текущая реализация сначала копирует подходящие группы в промежуточный `Array`, а затем собирает плоский ответ. При расширении промежуточного массива старые группы копируются целиком. Если большая группа была добавлена рано, она может копироваться при каждом расширении. Для `G` подходящих годов верхняя оценка с учётом этих копирований составляет O(log(Y + 1) + K log(G + 1)) при единичной стоимости копирования записи. На защите стоит различать оценку обхода с однократной выдачей и стоимость текущей реализации. При получении записей алфавитного указателя аналогично учитывается повторное копирование списков страниц при росте массивов. [Обход `range`](../../FirstLab/headers/BinaryTree.tpp#L326) · [Рост `Array`](../../../DataStructures/Array/Array.tpp#L66)

У алфавитного указателя в памяти находятся текст страниц и две копии пар «слово, список страниц». В `PersonIndex` каждая запись хранится в обоих индексах, а вызывающий код может держать исходную коллекцию для полного просмотра. Как альтернативу в индексах можно хранить номера записей в исходном массиве. Это уменьшит число копий строк, но потребует поддерживать соответствие номеров исходным записям при изменении массива.

Динамический массив проекта время от времени расширяется с увеличением ёмкости вдвое. Поэтому добавление в конец амортизированно требует постоянного числа операций над элементами, хотя отдельное расширение копирует уже сохранённые элементы. [Реализация `Array::push_back`](../../../DataStructures/Array/Array.tpp)

## 7. Эксперимент и проверка

### Как сравниваются алгоритмы

- Для алфавитного указателя оба метода получают одно слово и один построенный указатель. Сравниваются списки номеров страниц.
- Для `PersonIndex` поиск по дереву сравнивается с полным просмотром того же исходного набора по одному диапазону. Составной поиск показывается отдельно.
- В замер поиска входит формирование ответа. Сверка, отображение и экспорт выполняются отдельно. В консоли время поиска усредняется по повторным вызовам, поэтому единичный всплеск влияет на результат меньше.
- В консоли время построения измеряется отдельно на возрастающем, убывающем и перемешанном порядке входа. Перестановки готовятся заранее. Для указателя переставляются слова, то есть сохраняется набор слов с повторами, но разбиение на страницы может измениться. Для записей ключ порядка — год рождения с `id` при равенстве года. Составное дерево при этом сравнивает ключи начиная с имени. В каждом повторе строится локальный объект, который уничтожается до окончания замера, поэтому консольный замер включает его уничтожение.
- В консоли CSV сохраняет результаты и замеры построения. Консольные файлы с замерами построения — `alphabetical_index_build.csv` и `person_index_build.csv`. В GUI можно выгрузить таблицы результатов и замеров. GUI сбрасывает построенный индекс после изменения исходных данных.

Асимптотика описывает рост затрат. Стеночное время учитывает память, длину ключей, число повторов, размер выдачи и другие детали запуска. На защите корректно привязать вывод о скорости к показанному набору данных и диапазону. [Консольные замеры](../../../main.cpp) · [GUI указателя](../../../GUI/source/AlphabeticalIndexWidget.cpp) · [GUI индекса записей](../../../GUI/source/PersonIndexWidget.cpp)

### Какие сценарии проверяет тестовый набор

- UTF-8, сохранение переносов и совпадение двух способов поиска слова.
- Уменьшенные лимиты первой и десятой страниц.
- Сохранение пустых уменьшенных страниц и правильная нумерация.
- Ошибки при слишком маленьком размере страницы и слишком длинном слове.
- Несколько записей с одинаковым составным ключом, отсутствие точного совпадения и диапазон по году.
- Ошибка перевёрнутого диапазона, независимость сверки от порядка, чувствительность к изменению любого поля и количества повторов.

Для ручной проверки удобно воспроизвести примеры из разделов 3 и 5, затем проверить отсутствующее слово, диапазон на один год и диапазон без результатов. [Тесты ЛР-2](../tests/AlphabeticalIndexTests.cpp)

## 8. Вопросы на защите

| Вопрос | Краткий ответ |
|---|---|
| Что такое индекс? | Структура, построенная по исходным данным, которая позволяет по ключу найти запись, группу записей или их местоположение. |
| Чем индекс отличается от `Map`? | Словарь задаёт операции «ключ → значение». Индекс — применение этой структуры для поиска по данным. |
| Чем слово отличается от вхождения и записи указателя? | Написание — значение ключа. Вхождение — отдельная позиция в тексте. Запись указателя объединяет страницы всех вхождений одного написания. |
| Почему у вхождения нет класса? | Диаграмма описывает предметную область. Реализация различает вхождения по позициям в массиве, а связь со страницей определяет при разбиении. |
| Почему номер страницы есть только один раз? | При обработке по порядку для каждого слова поступают неубывающие номера. Повтор текущего номера возможен только в конце списка. |
| Почему можно получить отсортированный массив из дерева? | Симметричный обход обрабатывает меньшие ключи, затем узел и затем большие ключи. |
| Зачем дерево, если массив можно отсортировать? | Дерево удобно для вставок во время построения и нужно для выбранного сравнения. Для статического текста сортировка всех пар с последующей группировкой тоже подходит. |
| Бинарный поиск и поиск в дереве одинаковые? | У обоих логарифмическое число сравнений. Бинарный поиск делит диапазон индексов, а поиск в дереве выбирает ветвь от текущего узла. |
| Что будет с обычным деревом при возрастающих ключах? | Оно может выродиться в цепочку. Балансировка красно-чёрного дерева ограничивает высоту. |
| Что именно делает поворот? | Меняет локальные связи узлов и сохраняет порядок ключей. |
| Можно ли искать точное слово хеш-таблицей? | Да. Хеш-таблица удобна для точного равенства. Отсортированный вывод и диапазоны требуют порядка ключей. |
| Почему отдельный индекс по году? | Составной ключ начинается с имени, значит годы распределены между группами имён и фамилий. В дереве по году диапазон непрерывен в порядке обхода. |
| Что происходит с одинаковыми ключами у людей? | В дереве остаётся один ключ, а все записи добавляются в массив под ним. |
| Почему у людей сохранены повторы, а в указателе страницы уникальны? | Запрос по людям должен вернуть каждую входную запись. Указатель сообщает, на каких страницах встречается слово, поэтому повторные вхождения на той же странице дают один номер. |
| Зачем сравнивать все поля и учитывать повторы? | Две выборки одинакового размера могут содержать разные записи. Сверка по всем полям обнаруживает и замену записи, и изменение числа её копий. |
| Чем `all()` отличается от чтения исходной таблицы? | `all()` обходит индекс по году, поэтому упорядочивает выдачу по году. Исходная таблица хранит порядок ввода. |
| Когда полный просмотр может выиграть? | Для одного запроса индекс ещё нужно построить. При широком диапазоне обе выдачи содержат почти весь набор, а полный просмотр идёт последовательно. |
| Почему индекс сбрасывается после редактирования? | Ключи, состав групп или номера страниц могли измениться. Новый индекс должен строиться по актуальным данным. |
| Как честно сравнить время? | Взять одинаковые данные и запрос, измерить одну и ту же часть работы, в том числе формирование результата, и вынести вывод и сверку за пределы измерения. |
| Где посмотреть условие и проектные решения? | Условия по И-4 и И-5 описаны в задании, а выбор структур и наблюдаемое поведение — в дизайне. |

## 9. Задачи для самопроверки

1. **Страница меньшего размера.** Есть два вхождения `abcd`, обычный размер страницы 4. Какие номера попадут в указатель? Ответ — `[2, 3]`. Лимит первой страницы 2, поэтому она пустая.
2. **Повтор на одной странице.** На странице 2 стоит `дом дом`, а на странице 5 — `дом`. Ответ для `дом` — `[2, 5]`. Число вхождений равно 3.
3. **Точная вместимость.** На непустой странице осталось 3 символа, очередное слово имеет длину 3. Ответ — слово переносится дальше, поскольку перед ним нужен разделитель.
4. **Точный и диапазонный поиск.** В наборе три разных записи за 2002 год, две из них имеют одинаковые имя и фамилию. Точный запрос по этим полям и году вернёт две записи, диапазон `[2002, 2002]` — все три.
5. **Пропуск поддерева.** В узле 1998, искомый диапазон начинается с 2000. Ответ — левое поддерево пропускается, поиск продолжается справа.
6. **Остановка просмотра.** При обходе по возрастанию очередной год 2006, верхняя граница 2005. Ответ — завершить обход, поскольку уже обработаны все меньшие подходящие ключи.
7. **Дубликаты в сверке.** Выборки `[A, B, A]` и `[B, A, B]` содержат те же различные записи, но число повторов отличается. Ответ `samePersonRecords` — `false`.
8. **Оценка ответа.** В диапазон попали все N записей. Даже если ориентироваться по ключам быстро, индексированному поиску нужно сформировать N элементов ответа, поэтому время выдачи линейно по N.
