# Выполнение MiniLang через Visitor

`Interpreter` получает готовую программу `Array<UniquePtr<ast::Statement>>` и поток вывода. Лексер и парсер вызываются отдельно: до начала выполнения весь исходный текст должен успешно превратиться в AST.

Интерфейс находится в `interpreter/headers/interpreter.h`, реализация — в `interpreter/sources/interpreter.cpp`, тесты — в [InterpreterTests.cpp](../../../tests/Interpreter/InterpreterTests.cpp). Общие требования находятся в [ТЗ](../specification.md), устройство дерева — в [описании парсера](../parser/README.md).

## Пример запуска

```cpp
Parser parser;
const auto program = parser.parse(Lexer::tokenize(
    "remember x = 2 + 3 * 4\nprint x"
));

Interpreter interpreter;
interpreter.execute(program, std::cout);
```

Для примера нужны заголовки `lexer.h`, `parser.h`, `interpreter.h` из `interpreter/headers/` и `<iostream>`. В результате в поток попадёт `14.0` и перевод строки. Файлы запускаются через [CLI MiniLangCpp](../cli/README.md).

## Как Visitor запускает обработку

`Interpreter` реализует оба интерфейса: `ast::ExprVisitor` для выражений и `ast::StatementVisitor` для инструкций. Каждый узел через `accept` вызывает подходящую перегрузку `visit`. Проверять тип узла через `dynamic_cast` или `switch` исполнителю не нужно.

```text
execute
  └── Statement::accept
        ├── visit(Remember) → evaluate → Expr::accept → visit выражения → Map
        └── visit(Print)    → evaluate → Expr::accept → visit выражения → поток
```

Порядок обхода задаёт исполнитель. Для `Binary` он сначала полностью вычисляет левую ветвь, затем правую и только после этого применяет оператор. Выбор самого арифметического оператора остаётся в отдельной функции `applyNumericOperation`.

## Значения и промежуточный результат

`Value` — это `std::variant<double, bool, std::string>`. Числа представлены `double`, сравнения возвращают `bool`, строковые литералы превращаются в `std::string` без внешних кавычек. Экранирование не выполняется: обратная косая черта остаётся обычным символом.

Методы `visit` возвращают `void`, поэтому результат выражения передаётся через собственный `Optional<Value> lastValue`. Метод `evaluate`:

1. Сбрасывает предыдущий результат.
2. Вызывает `expression.accept(*this)`.
3. Проверяет, что посетитель записал значение.
4. Забирает его и снова сбрасывает промежуточный результат.

В бинарной операции левое значение хранится в локальной переменной до вычисления правого. Иначе вложенный обход перезаписал бы `lastValue`. Например, в `2 + 3 * 4` сначала сохраняется `2`, затем получается `12`, а общий результат становится `14`.

## Переменные и инструкции

Переменные хранятся в собственном `Map<std::string, Value>` на красно-чёрном дереве. Узлы программы принадлежат `Array` через `UniquePtr`; исполнитель их не копирует и не забирает владение.

`visit(Remember)` сначала вычисляет правую часть. Только при успехе он вызывает `insert` для нового имени или `replace` для существующего. Поэтому `remember x = x + 1` читает старое значение `x`, а ошибка в выражении не затирает его.

`visit(Identifier)` ищет имя через `containsKey` и `at`. Регистр значим, отсутствующее имя вызывает ошибку.

`visit(Print)` вычисляет выражение, переводит результат в текст и добавляет перевод строки. Пустая строка выводит только перевод строки. Логические значения выводятся как `true` и `false`.

## Операции и ограничения

Поддержаны `+`, `-`, `*`, `/`, `<`, `<=`, `>`, `>=`, `==`, `!=`. Каждый бинарный оператор требует два числа; автоматического преобразования строк и логических значений нет. Даже равенство строк пока не поддерживается.

Это сохраняет правило числовых операций Java-версии. Например, `print 1 < 2 < 3` разбирается парсером, но выполнение завершается ошибкой: результат первого сравнения имеет тип `bool`.

Строки можно сохранять в переменных и выводить. Конкатенация, условия, циклы, функции и унарные операции пока отсутствуют. Деление на положительный или отрицательный ноль вызывает ошибку, в отличие от поведения `double` в изученной Java-версии.

## Преобразование чисел и вывод

`std::from_chars` преобразует числовую лексему без зависимости от локали. Неполная запись, переполнение литерала и нечисловые значения отклоняются. В обычном пути лексер передаёт только последовательности цифр; дробные и отрицательные результаты получаются из выражений.

`std::to_chars` формирует короткую запись результата с сохранением значения `double`. Если у конечного числа нет десятичной точки, добавляется `.0`, в экспоненциальной записи — перед `e`. Например: `2.0`, `0.125`, `1.0e+20`. Арифметическое переполнение следует правилам `double`; для бесконечности и NaN используются записи `inf`, `-inf`, `nan`.

Сформированный текст записывается через `write` и `put`. Локаль, ширина поля и форматные флаги переданного потока не меняют представление значений и сами сохраняются. Полное совпадение числового форматирования с Java не требуется.

## Запуски и ошибки

Каждый `execute` очищает таблицу переменных и промежуточный результат. Один объект можно использовать для нескольких последовательных запусков, включая запуск после ошибки. Повторные и параллельные вызовы на одном объекте во время активного выполнения не поддерживаются.

Поток принадлежит вызывающему коду и должен существовать до завершения `execute`. При успехе и при исключении указатель на него сбрасывается; прямой вызов `visit(Print)` вне `execute` отклоняется.

При первой ошибке выполнение останавливается, уже записанный вывод остаётся в потоке. Ошибки языка выбрасываются как `std::invalid_argument` с префиксом «Ошибка выполнения». Отсутствующий результат выражения вызывает `std::logic_error`, сбой записи — `std::runtime_error` либо исключение самого потока. Координаты исходного текста пока отсутствуют.

## Проверки

Тесты охватывают контрольный пример ТЗ, приоритеты и вложенные выражения, арифметику и сравнения, строки, смену типа переменной, неизвестные имена, ошибки типов и деление на ноль. Отдельно проверяются порядок вычисления операндов, сохранение вывода до ошибки, независимость запусков, большое число переменных, локаль и форматирование потока, ошибка записи и некорректное AST.

Исходник исполнителя включён в библиотеку `MiniLangCore`; её используют CLI и `UnitTests`. Тесты исполнителя подключены к `UnitTests`. Штатные команды сборки и CTest приведены в корневом `AGENTS.md`.
