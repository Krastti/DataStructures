# Техническое задание: интерпретатор MiniLang на C++

## 1. Назначение и основание

Разработать учебный интерпретатор MiniLang на C++20, выполняющий программы из текстовых файлов `.mini` с использованием структур данных проекта DataStructures.

Основание — Java-проект [Krastti/MiniLang](https://github.com/Krastti/MiniLang). При подготовке ТЗ изучена локальная копия `/home/krastti/Workspace/MiniLang`: `Token.java`, `Lexer.java`, `Parser.java`, `Interpretator.java`, `Main.java` и `Documentation.md`. Доступ к GitHub отсутствовал; в локальной копии были незакоммиченные изменения лексера, парсера и тестов. Совпадение изученного состояния с опубликованной версией не подтверждено.

В изученной версии работают лексер, парсер рекурсивного спуска, AST, инструкции `remember` и `print`, арифметика, скобки и числовые сравнения. Переменные хранятся в `HashMap`, числа вычисляются через `Double`. Ключевые слова `when`, `otherwise`, `repeat` распознаются, но не выполняются. Строки представлены заготовками; унарные операции и дробные литералы пока не поддерживаются.

## 2. Общая схема

```text
Исходный текст → Токены → AST → Выполнение → Результат
                                      ↕
                               Таблица переменных
```

Интерпретатор не должен зависеть от Qt. Лексер и парсер не выполняют программу. До начала выполнения весь файл должен успешно пройти лексический и синтаксический анализ.

## 3. Возможности первой версии

```text
remember age = 19
remember nextAge = age + 1
print nextAge
print nextAge >= 18
```

- Инструкции разделяются переводами строк; поддерживаются LF и CRLF.
- Пустые строки разрешены, завершающий перевод строки необязателен.
- Пробелы и табуляции между токенами игнорируются.
- Имена чувствительны к регистру. В первой версии допустимы латинские буквы, цифры и `_`, причём цифра не может быть первым символом. Это документированное ограничение относительно Unicode-классификации символов в Java-лексере.
- `remember имя = выражение` создаёт переменную или заменяет её значение. Правая часть вычисляется до изменения переменной.
- `print выражение` выводит одно значение и перевод строки.
- Обращение к отсутствующей переменной вызывает ошибку.
- Типы значений: число двойной точности, логическое значение и строка. Логические значения получаются из сравнений и могут сохраняться в переменных. Строки в двойных кавычках можно сохранять и выводить; экранирование и многострочные литералы пока не поддерживаются.
- Каждый независимый запуск получает пустую таблицу переменных.

## 4. Выражения

| Приоритет, от высокого к низкому | Операции |
|---|---|
| Группировка | `(выражение)` |
| Умножение и деление | `*`, `/` |
| Сложение и вычитание | `+`, `-` |
| Сравнение | `<`, `<=`, `>`, `>=` |
| Равенство | `==`, `!=` |

Операторы одного уровня ассоциативны слева. Операнды вычисляются слева направо. Все бинарные операторы первой версии принимают два числа. Неявное преобразование логического значения в число запрещено. Поэтому результат сравнения можно сохранить и вывести, но нельзя использовать в арифметике или числовом сравнении.

Числовой литерал состоит из цифр; дробные результаты вычислений допустимы. Унарные `+` и `-` в первую версию не входят.

Деление на ноль должно выдавать ошибку выполнения. Это намеренное отличие от поведения `double` в текущей Java-реализации, допускающего бесконечность и `NaN`.

Формат вывода независим от системной локали: десятичный разделитель — точка, логические значения — `true` и `false`. Целые числовые результаты выводятся с `.0`. Полное побайтовое совпадение форматирования всех значений `double` с Java не требуется; остальные особенности форматирования описаны в [описании исполнителя](execution/README.md).

## 5. Компоненты

| Компонент | Ответственность |
|---|---|
| Лексер | Распознавание токенов и обнаружение недопустимых символов |
| Парсер | Проверка синтаксиса и построение AST |
| AST | Представление структуры программы |
| Значение | Хранение числа, логического результата или строки |
| Окружение | Создание, поиск и обновление переменных |
| Исполнитель | Последовательное выполнение инструкций, вычисление выражений |
| CLI | Чтение файла, запуск компонентов, вывод результатов и ошибок |

Исполнитель принимает готовое AST и переданный извне поток вывода. Компоненты должны допускать проверку без запуска CLI.

## 6. Использование структур данных

| Задача | Структура проекта | Требование |
|---|---|---|
| Токены | `Array<Token>` | Добавление в конец, чтение по индексу |
| Инструкции | `Array` или `ArraySequence` | Сохранение порядка программы |
| Переменные | `Map<std::string, Value>` | Поиск, добавление, замена значения |
| Владение AST | `UniquePtr` | Автоматическое освобождение узлов |
| Будущие области видимости | `Stack` | Добавление и удаление активных окружений |
| Стек вызовов функций | `Stack<CallFrame>` из `include/Stack/stack.h` | Добавление кадра при вызове, доступ к текущему кадру, удаление при возврате |

Допустимы `std::string`, потоки, средства работы с файлами и `std::variant`. Основные коллекции токенов, инструкций и переменных используют собственные контейнеры.

Перед выбором контейнера необходимо проверить совместимость с элементами. Поддержка перемещения контейнера не гарантирует поддержку некопируемых элементов `UniquePtr`. Необходимые доработки контейнеров должны быть минимальными, сопровождаться тестами и сохранять существующее поведение.

В первой версии рекурсивного исполнителя использование `Stack` необязательно. В дальнейшем стек окружений не должен требовать копирования некопируемого `Map`: способ хранения окружений выбирается отдельно с учётом интерфейса `Stack`.

При реализации функций стек вызовов должен использовать `Stack<CallFrame>`. `Array` остаётся контейнером последовательностей токенов, инструкций и аргументов. Кадр вызова хранит состояние вызова и его окружение; допускается некопируемый, перемещаемый `CallFrame`.

Для работы с такими кадрами необходимо доработать `Stack`:

- Заменить возврат копии из `top() const` перегрузками `T& top()` и `const T& top() const`. Доступ к текущему кадру не должен копировать его; ссылка действительна до удаления соответствующего узла или уничтожения стека.
- Обеспечить добавление перемещаемого некопируемого элемента через `push(T&& value)`. Внутри `push` и конструктора узла передавать значение перемещением до поля `data`, без промежуточного копирования. Сохранить добавление копируемых элементов из lvalue через отдельную перегрузку `push(const T& value)`.
- Сохранить корректное освобождение кадров при `pop`, уничтожении стека и раскрутке после ошибки. Определить и проверить поведение `top` и `pop` на пустом стеке.

Проверки должны использовать тип с удалёнными операциями копирования и доступным перемещением: добавление через `std::move`, изменение вершины по ссылке, чтение через константную ссылку, порядок LIFO и однократное освобождение ресурсов. Доработки стека обязательны перед реализацией функций; для первой версии без функций они не являются условием приёмки.

## 7. AST и управление памятью

Узлы выражений: числовой и строковый литералы, обращение к переменной, бинарная операция. Узлы инструкций: `Remember` и `Print`. Программа — упорядоченная последовательность инструкций.

AST имеет отдельную структуру. `BinaryTree` и `RedBlackTree` применяются как таблица имён: их упорядочивание и балансировка не подходят для синтаксических связей AST.

Владение узлами должно быть однозначным. При полиморфной реализации базовые типы имеют виртуальные деструкторы. Ошибки разбора и выполнения не должны приводить к утечкам, двойному освобождению и висячим ссылкам.

## 8. Диагностика

В текущей версии ошибка содержит этап обработки и понятное описание причины. `Token` хранит только `type` и `lexeme`; поля `line` и `column` пока не добавляются.

Будущая доработка диагностики: добавить в `Token` поля `line` и `column` с нумерацией от единицы, отслеживать положение в лексере и сохранять его в необходимых узлах AST. После этой доработки ошибки должны содержать строку и столбец. Пример будущего формата:

```text
Ошибка выполнения, строка 4, столбец 7:
Неизвестная переменная: total
```

Обязательные случаи: неизвестный символ, отсутствующее имя после `remember`, отсутствующий `=`, незакрытая скобка, пропущенный операнд, лишний токен после инструкции, неизвестная переменная, несовместимые типы и деление на ноль.

При первой ошибке обработка прекращается. При ошибке выполнения уже произведённый вывод сохраняется. При ошибке лексического или синтаксического анализа выполнение не начинается.

## 9. Запуск и интеграция

Отдельная цель CMake:

```text
MiniLangCpp path/to/program.mini
```

При успехе возвращается нулевой код, при ошибке — ненулевой. Результаты направляются в стандартный вывод, диагностика — в стандартный поток ошибок. Ошибки аргументов и чтения файла обрабатываются понятным сообщением.

Существующие CLI и GUI DataStructures сохраняют работоспособность. Интерпретатор собирается с `BUILD_GUI=OFF`. Новые тесты размещаются в `tests/Interpreter/` и регистрируются в CMake.

## 10. Проверка и приёмка

Добавить GoogleTest-тесты компонентов и сквозные тесты программ:

- пустой файл, LF/CRLF, отсутствие завершающего перевода строки;
- приоритеты, скобки, левая ассоциативность;
- создание, чтение и перезапись переменной;
- все арифметические операции и сравнения;
- ошибки синтаксиса, типов и выполнения;
- независимость таблиц переменных между запусками;
- освобождение частично построенного AST при ошибке.

Контрольная программа:

```text
remember x = 10
remember y = (x + 2) * 3
print y
print y >= 30
remember x = y / 2
print x
```

Ожидаемый вывод:

```text
36.0
true
18.0
```

Первая версия готова, когда контрольные и ошибочные сценарии проходят автоматически, проект собирается через CMake, основной путь обработки использует собственные контейнеры и существующие тесты продолжают проходить.

## 11. Последующее развитие

После базовой версии: дробные литералы и унарные операции; экранирование и операции над строками; `when … otherwise`; `repeat`; вложенные области видимости; функции, параметры и возврат значения.

Перед каждым расширением необходимо определить грамматику и семантику. Наличие ключевых слов в Java-лексере не устанавливает синтаксис блоков, условия цикла и правила областей видимости.

Порядок реализации описан в [плане](implementation-plan.md).
