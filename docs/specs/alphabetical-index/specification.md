# Спецификация алфавитного указателя

## Назначение

`AlphabeticalIndex` разбивает текст на страницы и строит соответствие «слово → номера страниц». Один указатель поддерживает бинарный поиск и поиск через `Map` на красно-чёрном дереве.

Задание И-4: 15 баллов, обязательная модификация И-4.1 — размер в символах, И-4.2 — учёт строк (+2). Всего за задачу 17 баллов без рейтинга методов поиска.

## Вход и представление данных

`build(const Array<std::string>& lines, size_t pageSize)` принимает исходные строки и размер обычной страницы. Возвращает готовый индекс; исходный массив не меняется.

- Слова выделяются через `std::istringstream >> word`: пробельные разделители не входят в слова.
- Регистр и пунктуация сохраняются: `кот`, `Кот` и `кот,` — разные ключи.
- Число символов считается по байтам UTF-8, которые не являются байтами продолжения. Корректность кодировки не проверяется; составные графемы не считаются одним знаком.
- `pagesByWord` хранит `Map<std::string, Array<size_t>>`, `orderedEntries` — упорядоченную выгрузку тех же данных, `pageContents` — текст страниц.
- Порядок ключей задаётся сравнением `std::string`, без языковой сортировки.

## Разбиение на страницы

Нумерация начинается с 1. Ёмкость первой страницы — `floor(pageSize / 2)`, каждой десятой — `floor(3 * pageSize / 4)`, остальных — `pageSize`.

Перед словом на непустой странице учитывается один символ разделителя. Если слово не помещается, создаётся следующая страница. Слово не разрывается. Между словами одной строки ставится пробел, перед первым словом новой непустой строки — `\n`. В начале страницы разделителя нет.

Повторные пробелы и табуляции сворачиваются; пустые строки не сохраняются. Поэтому результат сохраняет границы между непустыми строками, но не исходное форматирование целиком.

**Ограничение текущего алгоритма:** после перехода на следующую страницу её ёмкость повторно не проверяется. Слово, допустимое для обычной страницы, может превысить лимит десятой. Слишком длинное для первой страницы слово оставляет её пустой и переносится на вторую.

## Операции

| Метод | Результат |
|---|---|
| `build(lines, pageSize)` | Строит страницы и обе формы индекса |
| `findBinary(word)` | Копия массива номеров страниц; бинарный поиск в упорядоченных записях |
| `findTree(word)` | Копия массива номеров страниц; поиск по ключу в `Map` |
| `containsBinary(word)` | `true`, если бинарный поиск вернул непустой результат |
| `entries()` | Константная ссылка на упорядоченный массив `AlphabeticalEntry { word, pages }` |
| `pages()` | Константная ссылка на массив текстов страниц |

Отсутствующее слово даёт пустой массив. Номера страниц возрастают и не повторяются, даже если слово встречается на странице несколько раз. Ссылки из `entries()` и `pages()` действуют только пока существует соответствующее состояние владельца.

## Ошибки и пустой ввод

- `pageSize < 2` — `std::invalid_argument`.
- Слово длиннее `pageSize` — `std::invalid_argument`.
- Пустой ввод создаёт одну пустую страницу и пустой индекс.
- Ошибки выделения памяти и копирования передаются вызывающему коду.
- Для поиска следует использовать объект, возвращённый `build`: у объекта, созданного пустым конструктором, `pagesByWord` не инициализирован; `findTree` разыменует пустой указатель.

## Сложность

Пусть `u` — число разных слов, `w` — число слов, `p` — число страниц в ответе, `L` — длина текста. При постоянной стоимости сравнения ключей и амортизированном добавлении в `Array`:

| Операция | Время |
|---|---|
| Построение | `O(L + w log(u + 1))`, включая копирование текста и списков страниц |
| `findBinary`, `findTree` | `O(log(u + 1) + p)` |
| `containsBinary` | `O(log(u + 1) + p)`: текущая реализация копирует ответ |
| `entries`, `pages` | `O(1)` |

Сравнение строк дополнительно зависит от длины общего префикса. Память включает текст, временный массив слов и две копии соответствий «слово → страницы».
