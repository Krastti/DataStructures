# Алфавитный указатель: шпаргалка

## Основные понятия

- **Индекс** — дополнительная структура, позволяющая искать без полного просмотра исходных данных.
- **Ключ** — слово, по которому выполняется поиск.
- **Список вхождений** — здесь номера страниц, где встретилось слово.
- **Инвертированный индекс** — соответствие от слова к местам его появления. Алфавитный указатель — его частный случай.

```text
Страница 1: кот
Страница 2: мир кот

кот → [1, 2]
мир → [2]
```

Номер страницы хранится один раз: указатель отвечает на вопрос «где встречается», а не «сколько раз».

## Как строится указатель

1. Выделить слова из строк.
2. Посчитать длину слова и проверить место на странице.
3. При необходимости перейти на следующую страницу.
4. Добавить слово в текст страницы и её номер в список слова.
5. Выгрузить записи дерева по возрастанию ключей в массив.

В проекте разделители занимают место, первая страница имеет половинную ёмкость, каждая десятая — три четверти обычной. Размер в символах UTF-8 отличается от размера строки в байтах.

## Бинарный поиск

Предусловие — массив отсортирован тем же сравнением, которое используется при поиске.

Поддерживается полуинтервал `[first, last)`. Середина вычисляется как `first + (last - first) / 2`. Если ключ середины меньше искомого, левая граница становится `middle + 1`; иначе правая — `middle`. После схождения проверяется равенство ключа.

```text
[арбуз, дом, кот, мир, сад]   ищем «кот»
              ↑
          совпадение
```

Реализация ищет нижнюю границу: первый ключ, не меньший искомого. Само нахождение границы ещё не означает, что слово существует.

Каждая итерация примерно вдвое сокращает область поиска: `O(log u)` сравнений. Возврат копии списка из `p` страниц добавляет `O(p)`.

## Поиск через дерево

В `Map` ключи организованы красно-чёрным деревом: меньше — идём влево, больше — вправо, равенство — возвращаем значение. Балансировка обеспечивает логарифмическую высоту.

| Свойство | Упорядоченный массив | Красно-чёрное дерево |
|---|---|---|
| Поиск ключа | `O(log u)` | `O(log u)` |
| Добавление нового ключа | Обычно сдвиги `O(u)` | `O(log u)` |
| Размещение | Элементы массива подряд | Отдельные узлы и связи |
| В проекте | Готовая выгрузка для бинарного поиска | Построение и поиск указателя |

Одинаковая асимптотика не означает одинаковое время: влияют память, длина строк и копирование ответа.

## Что сказать на защите

- Почему две структуры? Дерево удобно для накопления ключей, массив позволяет сравнить другой алгоритм поиска на тех же словах.
- Откуда сортировка массива? Из упорядоченного обхода `Map::entries()`.
- Почему нет повторов страниц? Перед добавлением сравнивается последний номер; страницы обрабатываются последовательно.
- Что считается словом? Последовательность непробельных символов; удаление пунктуации и приведение регистра отсутствуют.
- Почему это не частотный словарь? Значение хранит страницы, а не количество появлений.
- Что измерять при сравнении? Построение отдельно от поиска, одинаковые запросы и данные; учитывать стоимость копирования результата.
